What the heck are Precision, Recall, and F1 Score?

Your model made a bunch of predictions. These three metrics reveal how trustworthy it actually is — and each one tells a totally different story.

Step 1 — The Building Blocks

Every prediction falls into one of 4 buckets

A classification model makes a decision: "Yes" or "No." But there are four different ways that can play out, and each one has a name. Once you know these four, the rest is simple math.

✅
True Positive (TP)
Correct Hit

It was spam, and the model correctly flagged it.

📬"Win a free iPhone!" → Flagged as spam ✓
✅
True Negative (TN)
Correct Pass

It wasn't spam, and the model correctly let it through.

📩"Meeting at 3pm?" → Allowed through ✓
⚠️
False Positive (FP) · "Type I Error"
False Alarm

It wasn't spam, but the model flagged it anyway. Also called "crying wolf."

😱"Your invoice is ready" → Wrongly flagged ✗
❌
False Negative (FN) · "Type II Error"
Missed It

It was spam, but the model missed it entirely. The real danger zone.

⚠️ Why not just use Accuracy?

Imagine a cancer model that just says "no cancer" for every single patient. If only 2% of people have cancer, it'd be 98% accurate — but completely useless. Precision and Recall expose this. Try it: set TP=0, FP=0, FN=5, TN=95 and watch accuracy look great while precision and recall both crash to zero.

Step 4 — The Tradeoff

Precision vs. Recall: the eternal push-and-pull

ML models don't output "yes/no" directly — they output a confidence score between 0–100%. You choose a threshold: above it, the model calls it positive. Below it, negative.

Move the threshold and watch precision and recall move in opposite directions. This is the core tradeoff every ML engineer navigates.

Step 5 — The Adjacent Vocab

Related terms you'll run into

Once you've got Precision, Recall, and F1, these nearby concepts snap into place. Click any to expand.

🎯 Accuracy

▼
The share of all predictions (both positive and negative) that were correct.
(TP + TN) ÷ (TP + TN + FP + FN)
Simple and intuitive — but dangerously misleading on imbalanced datasets. If 99% of emails are not spam, a model that always says "not spam" hits 99% accuracy while being totally useless.

🔭 Specificity (True Negative Rate)

▼
Recall, but for the negative class. "Of all actual negatives, how many did I correctly identify?"
TN ÷ (TN + FP)
In medical tests, specificity asks: "How good is this test at clearing a healthy person?" High specificity means fewer false alarms.

📈 AUC-ROC

▼
"Area Under the Receiver Operating Characteristic Curve." It measures how well a model separates positives from negatives across every possible threshold at once.

Score of 1.0 = perfect. Score of 0.5 = a coin flip. It's threshold-independent, making it great for comparing two different models head-to-head.

⚖️ Macro vs. Micro Averaging

▼
When you have more than two classes (e.g. cat / dog / bird), you need to combine per-class metrics.

Macro: Average each class equally — a rare class counts as much as a common one.
Micro: Pool all predictions together, weighting by class size.

When class sizes are very unequal, micro-averaging usually tells a more realistic story.

🪤 Type I vs. Type II Errors

▼
These come from classical statistics and map directly onto the confusion matrix:

Type I Error = False Positive — you cried wolf
Type II Error = False Negative — you missed the wolf

Which is worse? Totally depends on the domain. In cancer screening, a Type II error (missed diagnosis) is far worse. In spam detection, Type I (flagging a real email) might matter more.

🗂️ Confusion Matrix

▼
The 2×2 grid you've been playing with above. It lays out all four outcomes (TP, TN, FP, FN) at a glance, showing exactly where the model is getting confused.

For multi-class problems (e.g., recognizing 10 handwritten digits), it grows into an N×N matrix where each cell shows how often class A was mistaken for class B.
